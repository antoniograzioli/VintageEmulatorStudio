# Linux Build

VES supports Linux x86_64 Standalone and VST3 builds.

## Requirements

- Ubuntu 22.04 x86_64 or a compatible Linux build host.
- GCC/G++ 11 or compatible toolchain.
- JUCE/Projucer compatible with JUCE 8.0.13.
- Patched MAME 0.289 source under `validation/mame-0.289-patched`.

Install development dependencies on Ubuntu 22.04:

```bash
sudo apt install build-essential gcc-11 g++-11 make git python3 pkg-config \
  libsdl2-dev libsdl2-ttf-dev libasound2-dev libfontconfig1-dev \
  libfreetype6-dev libcurl4-openssl-dev libgl1-mesa-dev \
  libx11-dev libxext-dev libxinerama-dev libxrandr-dev libxcursor-dev \
  libxi-dev libgtk-3-dev libwebkit2gtk-4.0-dev
```

SDL2 and SDL2_ttf are required by the Linux MAME OSD payload. PortAudio, PipeWire, and PulseAudio backends are disabled in the embedded MAME build. Ubuntu's SDL2 may load or link PulseAudio transitively; this is not a direct VES or MAME audio backend dependency.

## MAME PIC Artifacts

The MAME objects and static archives are linked into both an executable and a VST3 shared object. Every MAME object/archive that can reach the VST3 link must be built with `-fPIC`.

The release script builds these Phase 1 MAME artifacts automatically when they
are missing. The underlying MAME command is:

```bash
make -j2 \
  SUBTARGET=vesembedded \
  OSD=sdl \
  PTR64=1 \
  OVERRIDE_CC=gcc \
  OVERRIDE_CXX=g++ \
  ARCHOPTS=-fPIC \
  USE_QTDEBUG=0 \
  NO_USE_MIDI=0 \
  NO_USE_PORTAUDIO=1 \
  NO_USE_PIPEWIRE=1 \
  NO_USE_PULSEAUDIO=1
```

`USE_QTDEBUG=0` avoids the Qt debugger dependency. `NO_USE_MIDI=0` keeps MAME MIDI enabled; PortMidi is statically linked and uses ALSA on Linux. Do not omit `ARCHOPTS=-fPIC`.

On limited-memory hosts, use at most `-j2`. If Lua/frontend translation units exhaust memory, build those units with `-j1`. The release script serially prebuilds the detected Lua frontend objects before the normal `-j2` JUCE build.

## Projucer Regeneration

The Linux JUCE project file is:

```text
platform/linux/VintageEmulatorStudio.linux.jucer
```

It generates into:

```text
Builds/LinuxMakefile/
```

`Builds/LinuxMakefile/Makefile` is generated by Projucer. `Builds/LinuxMakefile/LinuxMameIntegration.mk` carries the Linux MAME/JUCE integration and must remain alongside the generated Makefile. The release script restores the include and VST3 manifest-helper link hook after regeneration.

The Linux `.jucer` uses repository-relative VES/MAME source paths. JUCE itself must be supplied by the build host through Projucer global module paths, `PROJUCER`, or `JUCE_ROOT`.

Repair integration without building:

```bash
platform/linux/build-linux-release.sh --integrate-only
```

Regenerate and then build:

```bash
PROJUCER=/path/to/Projucer platform/linux/build-linux-release.sh --regenerate
# or
JUCE_ROOT=/path/to/JUCE platform/linux/build-linux-release.sh --regenerate
```

If neither is set, the script checks `Projucer` on `PATH`. Ensure Projucer's global JUCE module path points to a compatible JUCE checkout before resaving.

## VES Build

From a clean checkout:

```bash
platform/linux/build-linux-release.sh
```

The script builds missing Phase 1 MAME artifacts, cleans only JUCE Release outputs, serially builds large Lua frontend objects, builds Standalone and VST3 with a maximum of `-j2`, disables JUCE's automatic `~/.vst3` copy, creates `Dist/Linux/x86_64`, strips debug information only from `Dist` copies, normalizes `moduleinfo.json`, and performs static validation. It does not rebuild MAME when the expected artifacts are already present.

Outputs:

```text
Dist/Linux/x86_64/Standalone/
  Vintage Emulator Studio
  Resources/plugins/
  Resources/artwork/

Dist/Linux/x86_64/VST3/
  Vintage Emulator Studio.vst3/Contents/
    x86_64-linux/Vintage Emulator Studio.so
    Resources/moduleinfo.json
    Resources/plugins/
    Resources/artwork/
```

ROMs, user media, NVRAM, settings, PSDs, `.DS_Store`, AppleDouble metadata, and editor backup files are not packaged.

For manual installation after validation, copy the complete VST3 bundle to:

```text
~/.vst3/Vintage Emulator Studio.vst3
```

## Runtime Dependencies

The release uses normal distribution-provided libraries: glibc, libstdc++, libgcc_s, SDL2, SDL2_ttf, ALSA, X11/Xi, OpenGL, Fontconfig, FreeType, and curl, plus their normal transitive dependencies. Arbitrary Ubuntu system libraries are not bundled.

The final ELF files must not have direct NEEDED entries for PortAudio, PipeWire, or PulseAudio. PulseAudio may appear only transitively through the distribution SDL2 package.
